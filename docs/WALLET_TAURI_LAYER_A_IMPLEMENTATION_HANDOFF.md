## Implemented boundary

The implementation adds exactly seven qualification-only `#[tauri::command]` wrappers under:

`#[cfg(all(test, feature = "wallet-layer-a-qualification"))]`

The exact command names are:

- `wallet_get_status`
- `wallet_select_recovery_destination`
- `wallet_create`
- `wallet_select_recovery_source`
- `wallet_restore`
- `wallet_unlock`
- `wallet_lock`

The harness:

- builds an actual `tauri::generate_handler!` table;
- creates a Tauri `MockRuntime` application and WebView window;
- invokes each generated wrapper through `tauri::test::get_ipc_response` and the real invoke resolver;
- uses the existing `WalletInvokeRequest` whole-message `CommandArg`;
- parses with the production `parse_envelope` implementation;
- uses only a non-custody classifier after parsing;
- returns only pre-serialized `tauri::ipc::Response` or fixed `InvokeError` values;
- records only counters, fixed results, and a revoked flag;
- contains no wallet runtime, lifecycle adapter, vault, recovery, Core, seed, signing, submission, or AppManifest authority; and
- cannot compile unless both `cfg(test)` and the explicit qualification feature are active.

- replay after revocation with no stale success; and
- normalized duplicate textual top-level keys.

The duplicate textual-key case deliberately demonstrates that a payload already normalized into
`serde_json::Value` can reach the wrapper as last-key-wins data. Layer A still cannot independently
prove duplicate-key rejection. Production uses the separately accepted Layer B raw-transport proof,
so the current regression verifies that the production policy remains `true` without attributing
that result to Layer A.

For a remote origin, Tauri rejects the invoke before the wrapper runs with the exact framework error `wallet_get_status not allowed. Plugin not found`. No request value or canary is returned and the classifier does not execute, but this is not a wallet fixed-vocabulary error. Layer A therefore does not close the design requirement concerning raw framework errors; Layer B must qualify the real packaged transport behavior before any exposure decision.

Existing private-boundary tests continue to cover zero or wrong HWND, stale epoch, replaced identity, lifecycle invalidation, selection cancellation, and fail-closed runtime behavior. These tests are supporting evidence; they do not replace the required Layer B transport qualification.

## Windows test-executable manifest

Tauri's mock resolver causes the Windows library-test executable to retain a Common Controls v6 entry point. Cargo's unit-test executable does not inherit the application resource generated by `tauri-build`, so it initially terminated before test execution with `STATUS_ENTRYPOINT_NOT_FOUND`.

The opt-in Layer A feature compiles one Common Controls v6 resource for the isolated `--lib` test
target. It does not add parallel linker manifest switches alongside Tauri's application resource.
This avoids duplicate Windows `MANIFEST` resources while allowing Tauri's dialog-linked test
executable to start and retaining the same generated-wrapper and resolver path used by the focused
qualification tests. `embed-resource` is already pinned transitively in `Cargo.lock`; making that
build-only use explicit does not introduce new package bytes or runtime code.

The exact focused command is:

```powershell
cargo test --manifest-path src-tauri/Cargo.toml --features wallet-layer-a-qualification --lib generated_wrapper_qualification -- --nocapture
```
